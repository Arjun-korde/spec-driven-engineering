# Feedback record [book ch 29]

Delete sections that do not apply. One record per feedback item.

```
Feedback ID:
Date:
Source:
Affected requirement or artifact: REQ-[###] / [artifact]
Feedback summary:
Evidence or example:
Decision needed:
Owner:
Status: New / Under review / Accepted / Rejected / Deferred
Spec update required: Yes / No
Test update required: Yes / No
```

Guidance:
- Good feedback names the affected requirement, explains the gap, proposes a decision, and states who owns the next action. [book ch 29]
- Type (clarification, bug, design concern, scope request, operational concern) decides where it is recorded and who owns it; see `references/11-roles-and-handoffs.md` section 6.
- If the status becomes Accepted and the spec changes, open a change record CHG-### (`templates/spec-change-record.md`). [addition]
- Scope requests are not accepted until requirement, design, tests, tasks, and review checklist are updated. [book ch 29]
