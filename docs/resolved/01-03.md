# Resolved book inconsistencies: references 01 (intent), 02 (requirements and PRD), 03 (technical design)

Each line records a place where the book contradicts itself or leaves a gap, and the choice this skill makes. All are [addition] unless a book source is cited.

## 01 - Intent
- "Project brief" (ch1) vs "Engineering Intent Document" (ch2, ch4 `intent.md`): one artifact, named Intent. [addition]
- Field lists differ: ch2 lists problem, users, goals, capabilities, out of scope, constraints, success criteria; Appendix A lists business goal, user goal, pain points, desired outcome, success measures, open questions. Secondary users and risks appear in the ch2 example, prompt, and checklist (secondary users in the example; risks in the prompt; both in the checklist) but not the ch2 field list. The template carries both sets. [addition]
- Prompt 3.4 ends "Do not move to implementation" even for late stages: reworded to "do not start work belonging to a later stage". [addition]
- Boundary between "constraint" and "out of scope" is undefined in the book: constraint = a limit on how it is built or run; out of scope = a capability deliberately not built. [addition]

## 02 - Requirements and PRD
- Book IDs REQ-F/REQ-NF/REQ-R/BR/CON (ch5) vs plain REQ-001 (Appendix B): unified to `REQ-###` with a Type column. The book's role template had no REQ-R slot but its example used REQ-R; roles are now a table plus optional REQ rows. [addition]
- Book `AC-###` kept; ACs link to REQ via a column. [addition]
- Priority labels: ch6 uses Must/Should/Could/Later; Appendix B uses Must/Should/Could/Won't. The skill uses Won't, which is the book's own Appendix B wording. [book ch6, App B]
- Goal format has a constraint slot in the format but not in the PRD template; the slot is kept optional. [addition]
- Out-of-scope table has a "Future status" column but the PRD template does not; the column is kept. [addition]
- Story-to-REQ/TASK/TEST link existed only in the standalone story format; kept in the template. [addition]
- Book's performance numbers differ across chapters (illustrative); none are copied. [addition]
- Book says PRD holds no technical content yet shows a performance metric in an example; performance targets live in requirements as nonfunctional REQs, and the PRD metric may reference them. [addition]
- "Pending / in progress / complete" status wording differs in the book; skill task status vocabulary is todo | doing | blocked | review | done (applies to tasks, not product states). [addition]
